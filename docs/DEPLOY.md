# Инструкция по запуску Хань-Лаб by Nova

Эта инструкция поможет вам развернуть приложение на GitHub Pages с базой данных Supabase.

## Что нужно перед началом

- Аккаунт GitHub (бесплатный)
- Аккаунт Supabase (бесплатный)
- Около 20-30 минут времени

## Шаг 1. Подготовка репозитория GitHub

Если вы ещё не создали репозиторий:
1. Зайдите на https://github.com и создайте новый репозиторий (например, `han-lab`)
2. **Важно:** имя репозитория должно совпадать с `base` в `vite.config.ts` (строка 7)
3. Если имя репозитория отличается, измените `base: '/han-lab/'` на `base '/ваше-имя/'`

## Шаг 2. Supabase

1. Зайдите на https://supabase.com и зарегистрируйтесь
2. Нажмите "New Project"
3. Заполните форму:
   - **Name:** `han-lab`
   - **Database Password:** (сгенерируйте надёжный пароль и сохраните в менеджере паролей)
   - **Region:** выберите регион ЕС (например, Frankfurt)
   - **Pricing Plan:** Free
4. Нажмите "Create new project" и подождите 2-3 минуты

### Настройка базы данных

1. В левом меню нажмите "SQL Editor"
2. Нажмите "New query"
3. Скопируйте содержимое файла `supabase/migrations/001_init.sql` из проекта
4. Вставьте в редактор и нажмите "Run" (или Ctrl+Enter)
5. Убедитесь, что нет ошибок

### Настройка авторизации

1. В левом меню нажмите "Authentication" → "Providers"
2. Включите "Email":
   - Нажмите на "Email"
   - Включите "Confirm email" (подтверждение по ссылке)
   - Включите "Secure email change"
   - Нажмите "Save"

### Настройка URL

1. В левом меню нажмите "Authentication" → "URL Configuration"
2. **Site URL:** пока оставьте временным (например, `http://localhost:5173`)
3. **Redirect URLs:** добавьте `http://localhost:5173/**`
4. Нажмите "Save"

### Получение ключей

1. В левом меню нажмите "Project Settings" → "API"
2. Скопируйте:
   - **Project URL:** (начинается с https://xxx.supabase.co)
   - **anon public:** (длинный ключ)
3. **Не копируйте** `service_role` — это секретный ключ!

## Шаг 3. Настройка GitHub Secrets

1. В GitHub откройте ваш репозиторий
2. Перейдите в "Settings" → "Secrets and variables" → "Actions"
3. Нажмите "New repository secret"
4. Добавьте два секрета:

   **Secret 1:**
   - **Name:** `VITE_SUPABASE_URL`
   - **Value:** (вставьте Project URL из шага 2)
   - Нажмите "Add secret"

   **Secret 2:**
   - **Name:** `VITE_SUPABASE_ANON_KEY`
   - **Value:** (вставьте anon public key из шага 2)
   - Нажмите "Add secret"

## Шаг 4. Загрузка кода в GitHub

### Если вы ещё не загружали код:

1. Откройте терминал в папке проекта
2. Инициализируйте git:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   ```
3. Добавьте удалённый репозиторий (замените `USERNAME` на ваш ник):
   ```bash
   git remote add origin https://github.com/USERNAME/han-lab.git
   git branch -M main
   git push -u origin main
   ```

### Если код уже в репозитории:

Просто сделайте `git push` после изменений.

## Шаг 5. Включение GitHub Pages

1. В GitHub откройте репозиторий → "Settings"
2. В левом меню выберите "Pages"
3. В разделе "Build and deployment":
   - **Source:** выберите "GitHub Actions"
4. Нажмите "Save"

**Важно:** Не выбирайте "Deploy from a branch" — мы используем GitHub Actions для автоматического деплоя.

## Шаг 6. Первый деплой

1. После пуша кода в GitHub автоматически запустится workflow "Deploy to GitHub Pages"
2. Перейдите в "Actions" → "Deploy to GitHub Pages"
3. Подождите завершения (обычно 1-2 минуты)
4. После успешного деплоя сайт будет доступен по адресу:
   `https://USERNAME.github.io/han-lab/`

## Шаг 7. Обновление Supabase URL

1. Вернитесь в Supabase → "Authentication" → "URL Configuration"
2. **Site URL:** вставьте адрес вашего сайта (например, `https://USERNAME.github.io/han-lab/`)
3. **Redirect URLs:** добавьте `https://USERNAME.github.io/han-lab/**`
4. Нажмите "Save"

## Шаг 8. Проверка

Откройте сайт на телефоне и компьютере:

1. **Гостевой режим:**
   - Нажмите "Начать без аккаунта"
   - Перейдите на вкладку "Повторение"
   - Пройдите тестовые карточки

2. **Регистрация:**
   - Вернитесь на приветствие (очистите localStorage или откройте в инкогнито)
   - Нажмите "Создать аккаунт"
   - Введите e-mail и пароль (минимум 10 символов)
   - Проверьте почту — должно прийти письмо с подтверждением

3. **Тоны:**
   - Перейдите на вкладку "Тоны"
   - Разрешите доступ к микрофону
   - Запишите слово и проверьте анализ

4. **Профиль:**
   - Перейдите на вкладку "Профиль"
   - Проверьте статус синхронизации
   - Нажмите "Экспорт данных" — должен скачаться JSON файл

## Шаг 9. GitHub Actions для бэкапа (опционально)

Для автоматического бэкапа и проверки активности:

1. В GitHub → "Settings" → "Secrets and variables" → "Actions"
2. Добавьте дополнительные секреты:
   - **Name:** `SUPABASE_URL`
   - **Value:** (Project URL)
   
   - **Name:** `SUPABASE_ANON_KEY`
   - **Value:** (anon public key)
3. Workflows `keep-alive.yml` и `backup.yml` уже настроены в проекте

## Шаг 10. Свой домен (опционально)

Если хотите свой домен:

1. Купите домен (например, `hanlab.ru`)
2. В GitHub → "Settings" → "Pages" → "Custom domain"
3. Добавьте ваш домен
4. Следуйте инструкциям GitHub для настройки DNS

## Лимиты бесплатных тарифов (на 2026 год)

**GitHub Pages:**
- Статический хостинг: безлимит
- Трафик: 100 ГБ в месяц
- GitHub Actions: 2000 минут в месяц

**Supabase Free:**
- База данных: 500 МБ
- Файлы: 1 ГБ
- Активные пользователи: 50 000 в месяц
- API запросы: безлимит
- Проект ставится на паузу после недели неактивности

Когда нужно перейти на платный тариф:
- База данных заполнена > 400 МБ
- Проект ставится на паузу и это мешает
- Больше 40 000 активных пользователей в месяц
- Превышен лимит GitHub Actions

## Подключение SMTP для писем (для публичного запуска)

Встроенная почта Supabase сильно ограничена. Для публичного запуска:

1. Зарегистрируйтесь на SMTP провайдере с бесплатным тарифом (например, SendGrid, Mailgun)
2. В Supabase → "Project Settings" → "Auth" → "SMTP Settings"
3. Включите "Enable SMTP"
4. Введите данные от SMTP провайдера
5. Нажмите "Save"

## Устранение проблем

**Сайт не загружается:**
- Проверьте "Actions" → "Deploy to GitHub Pages" — есть ли ошибки в логах
- Убедитесь, что GitHub Pages включён в настройках
- Проверьте, что `base` в `vite.config.ts` совпадает с именем репозитория

**Регистрация не работает:**
- Проверьте Secrets в GitHub Settings
- Проверьте URL в Supabase Authentication
- Убедитесь, что таблицы созданы в SQL Editor

**Микрофон не работает:**
- Убедитесь, что сайт открывается по HTTPS (GitHub Pages автоматически даёт HTTPS)
- Проверьте разрешения браузера

**Синхронизация не работает:**
- Проверьте, что таблицы созданы (SQL Editor)
- Проверьте RLS политики (должны быть включены)
- Проверьте консоль браузера на ошибки

**Изменения не применяются после пуша:**
- GitHub Actions деплоит автоматически при пуше в ветку `main`
- Проверьте статус деплоя в "Actions"
